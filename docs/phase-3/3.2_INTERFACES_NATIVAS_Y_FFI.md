# 3 Núcleo compartido en Rust — 3.2 Interfaces nativas y FFI

## 3 Núcleo compartido en Rust

### 3.2 Interfaces nativas y FFI

**Objetivo del ROADMAP:** establecer frontera Python ↔ Rust y C/C++ ↔ Rust para el futuro cliente Android.

**Artefactos:**
- `core/rust/src/ffi.rs`: símbolos C ABI versionados con `extern "C"`, control de errores y captura de panic; ningún secreto compartido.
- `core/rust/include/smartuni_core.h`: cabecera para C/C++ y adaptador Android NDK futuro.
- `core/rust/examples/cpp/smoke.cpp`: aplicación C++ de prueba con llamadas enlazadas a la biblioteca real en Linux; en Android se compila con NDK para ARM64.
- `apps/desktop/smart_uni/native_bridge.py`: carga explícita mediante `SMARTUNI_NATIVE_LIB` o ruta local; biblioteca invocada con `ctypes`. No participa en `main.py` ni modifica el comportamiento existente. No se carga de manera silenciosa ni descarga un binario.
- `apps/desktop/tests/test_phase3_native.py`: pruebas reales contra la librería compilada cuando `SMARTUNI_NATIVE_LIB` está presente. Las pruebas Tkinter convencionales no requieren el binario y omiten estas pruebas, lo cual se registra.

**ABI 1:** `smartuni_abi_version()` devuelve 1; `smartuni_validate_email_v1(ptr,len)` y `smartuni_validate_operation_v1(ptr,len)` devuelven 0 en éxito, -1 ante puntero/tamaño inválido, -2 ante dato inválido y -3 en caso de panic capturado. `smartuni_crypto_self_test_v1()` ejecuta vectores criptográficos fijos; no recibe claves ni documentos.

**Contrato de memoria:** punteros de entrada válidos durante toda la llamada, longitud verificable, ningún buffer devuelto ni ownership cruzado, ninguna excepción Rust debe cruzar la frontera C. Los punteros arbitrarios proporcionados por código nativo no confiable pueden causar errores de memoria; este prototipo FFI no representa un sandbox.

**Android:** el workflow compila `cdylib` para `aarch64-linux-android` y comprueba que un compilador del NDK acepta el consumidor C++; esto **no** implementa Java/JNI, cliente Android, comunicación nativa o verificación en dispositivo, todos pendientes de la etapa 8. No atribuir al simple hecho de usar C++/Rust seguridad en endpoints.

**Pruebas:** Windows y Linux compilan y ejecutan librería Rust, Rust tests y puente Python. Linux enlaza y ejecuta C++; Android ARM64 se compila pero no se ejecuta. La evidencia exacta queda en el acta de cierre.
