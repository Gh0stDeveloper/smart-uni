# 9.2 Compilación y actualización

## Integrado

- CI multiplataforma existente Windows/Linux/Rust/API/web y CI Android Java↔C++/JNI↔Rust se mantiene; release Android activa R8, shrinking y reglas explícitas que conservan métodos JNI.
- Android workflow agrega acceso KVM, parámetros de emulator/boot y logcat de falla. La ejecución previa [#42296402993](https://github.com/Gh0stDeveloper/smart-uni/actions/runs/42296402993) compiló APK/AAB pero **falló instrumentación** (ADB offline, Process crashed, cero tests). Hasta una ejecución satisfactoria se mantiene bloqueado.
- Verificador offline scripts/phase9_release_policy.py: firma Ed25519 separada sobre bytes exactos de manifiesto, SHA-256 y tamaño de artefacto, identidad de paquete, canal, commit fuente, versionCode y política anti-downgrade. Pruebas negativas emplean firma sintética. El servidor no puede introducir una nueva clave pública de confianza desde el propio manifiesto.
- Regla de rollback: prohibir instalar versiones antiguas; para volver a código estable, reempaquetarlo con versionCode estrictamente mayor, comprobar migraciones, firmar y desplegar por un canal previamente autorizado. No se ha implementado este mecanismo en la aplicación ni en un servidor.

## Contrato de manifiesto de release (experimental)

Campos obligatorios: schema_version = 1, package_name = xyz.smartuni.app, channel = internal|closed|production, version_code, min_supported_version_code, artifact_sha256, artifact_size y source_commit. Firma Ed25519 Base64 separada del archivo JSON original. Clave pública entregada por un canal independiente y versionCode local respaldado por almacenamiento protegido. El verificador en Python es SOLO una utilidad offline de validación para pipelines y no un actualizador del cliente.

## Bloqueos reales

- APK/AAB release aún sin firma comercial ni artefactos probados para Play: se requieren credenciales fuera de Git, comprobaciones de certificados con apksigner y jarsigner y validación física.
- No existen actualización Play/desktop integrada, firma del instalador Windows/Linux, validación en el cliente, rollback transaccional ni pin de clave confiable en el cliente.
- Faltan lockfiles comprometidos, SBOM, gestión de CVE, IdP/HTTPS desplegados y recuperación cifrada multi-dispositivo.
- La app Android todavía puede perder el único apunte si se elimina la clave Android Keystore.

**Estado de 9.2: parcial**, ningún canal de release aprobado.
