## 6 Cifrado y gestión de claves

### 6.3 Interoperabilidad y revisión

**Fronteras probadas:** Rust `smartuni-core` produce blobs `SUAEAD01` que la implementación independiente `cryptography`/OpenSSL puede descifrar; Python produce el mismo formato autenticado y Rust lo descifra mediante C ABI en Linux/Windows. Para `SURECV01`, Rust Argon2id se valida contra `argon2-cffi` + AESGCM de Python/OpenSSL, en ambas direcciones. El test C++ enlaza el ABI de cifrado real en Linux; el target Android ARM64 genera biblioteca `.so` y compila consumidor C++ con NDK, **sin ejecutar Android ni integrar JNI**.

**Pruebas criptográficas negativas obligatorias:** contexto de propietario cruzado, ciphertext y tag alterados, nonce/header/magic cambiados, clave equivocada, longitud/sobretamaño inválido, recuperación con frase incorrecta, paquete modificado y llave de backup que no corresponde a la base. Las claves son sintéticas aleatorias y permanecen en la memoria de CI; no se usa ningún archivo de usuarios ni credenciales reales.

**Pruebas reales de material protegido:** SQLCipher + Rust en Windows/Linux, importación de archivo sintético → `SUAEAD01` en disco, snapshot/outbox transaccional, lectura de bytes de memoria sin temporary plaintext, borrado de material, rechazo de adjuntos alterados y recuperación con clave perdida. El legacy sigue intacto y sin protección efectiva: no es una prueba del modo productivo.

**Limitaciones de QA pendientes:** pruebas con dispositivo Android físico/emulador, login OIDC real, control de acceso local por sesión, ejecución de PKI/KeyStore hardware, archivos grandes en streaming, corte eléctrico entre publicación de blob y transacción, escaneo de contenido y lecturas con antivirus/visor externo, fuzzing de C ABI, reporte de auditoría externa, pruebas de rotación/migración de millones de archivos y paquetes firmados.

**Criterio de cierre técnico:** Rustfmt, Cargo tests/Clippy, binario Windows/Linux con pruebas FFI y Python independientes, compilación Android NDK, SQLCipher y Tkinter sin regresiones, documentación de riesgos; **no** se afirma seguridad E2EE de producción. Evidencia exacta y commits en [acta de etapa 6](6_CIERRE_Y_EVIDENCIAS.md) cuando el CI final concluya.
