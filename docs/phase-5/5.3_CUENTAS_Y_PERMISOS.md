# 5 Backend, identidad y autorización — 5.3 Cuentas y permisos

## 5 Backend, identidad y autorización

### 5.3 Cuentas y permisos

**Límite de confianza:** Browser → portal Next.js/servidor Auth.js → IdP OIDC externo (no conectado); Next.js BFF → FastAPI con Authorization: Bearer; FastAPI → PostgreSQL. Los parámetros de usuario, email, subject, actor_ref y claims role no autorizan nada sin verificación del bearer y lectura del usuario desde PostgreSQL.

**Identidad:** Auth.js 5 beta.32 usa Authorization Code + PKCE S256, state y nonce y requiere un cliente confidencial del IdP. FastAPI comprueba JWT RS256, emisor HTTPS configurado, audience del recurso, fechas de emisión y expiración, subject no vacío y JWKS preconfigurado. Los tests usan llaves RSA reales **sintéticas**, no tokens sin firma. Se registra cuenta nueva con rol student; no existe endpoint para elevarse a admin. Un operador puede promover una identidad tras revisión con privilegios SQL fuera de la API. Un JWT con campo role=admin NO concede ese rol.

**Autorización:** SELECT/UPDATE/DELETE de notes filtra explícitamente Note.owner_id == Identity.id. Otro usuario siempre ve 404 y no modifica el recurso. Métricas admin requieren rol admin recuperado de PostgreSQL. No se acepta X-Actor-Ref para suplantar.

**Sesiones:** hashes SHA-256 de tokens revocados se guardan en revoked_tokens y se consultan en cada petición protegida. Revocar un token bloquea ese mismo token sin cerrar otro bearer válido. El portal solicita revocación de API en logout; la sesión Auth.js se borra incluso si la API remota está caída. Eso no significa revocación global de IdP ni invalidez del access token ante otros servicios.

**Credenciales desktop heredadas:** se limita PBKDF2 del JSON a 100 000–1 000 000 rondas con sal de 16 bytes y digest de 32 bytes, para evitar iteraciones arbitrarias enviadas por archivo alterado; 260 000 rondas del prototipo siguen validándose. No se ha migrado a Argon2id (depende de gestión de credenciales e IdP). [Regresión Windows/Linux](https://github.com/Gh0stDeveloper/smart-uni/actions/runs/42225588765) incluye tres pruebas nuevas de costo de hash. El resto del escritorio permanece funcional en modo legacy.

**Pruebas:** API PostgreSQL 16 14/14 tests con tokens RSA auténticos, aislamiento, SQL injection, claims inválidos, revocación y sesión independiente. Portal 3/3 controles y HTTP 401/403 reales. No hubo prueba interactiva de OIDC con proveedor externo; no se desplegó Keycloak real, IdP de producción ni servidor TLS.

**Pendientes que NO se cierran:** autorización de StudentSpaceService local (P02), cuenta demo legacy (P03), Argon2id y proveedores reales (P16), refresh/logout global y cookie/proxy real (P31/P32), aplicación Android y E2EE (P14/P15). La validación productiva está en etapas 6/7/8/9.
