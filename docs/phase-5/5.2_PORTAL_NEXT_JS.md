# 5 Backend, identidad y autorización — 5.2 Portal Next.js

## 5 Backend, identidad y autorización

### 5.2 Portal Next.js

**Implementación verificada:** `apps/web` contiene Next.js 16.4.5 + TypeScript y Auth.js v5 beta.32; esta versión incluye el parche de [advisory GHSA-8fpg-xm3f-6cx3](https://github.com/nextauthjs/next-auth/security/advisories/GHSA-8fpg-xm3f-6cx3). Se reutiliza el **mismo blob del icono original**, colores azul/turquesa y diseño limpio de SMART UNI sin panel lateral derecho adicional.

**BFF / seguridad:** sesión cifrada y cookie HttpOnly gestionada por Auth.js, PKCE + state + nonce configurados en proveedor OIDC Keycloak. `session` del navegador NO recibe token bearer; `getToken` del lado servidor lo recupera de cookie cifrada. Se requiere session.user.id concreto, no basta con comprobar que auth() retorne un objeto. El BFF valida URL HTTPS fija del backend en producción, limita respuesta, no sigue redirects, usa no-store y timeout, exige Origin exacto para POST y corta respuesta antes de hablar con el backend si falta sesión. Roles y propietarios se verifican **en FastAPI** con datos de PostgreSQL, nunca en CSS/claims del cliente.

**Pantallas:** Inicio, espacio académico con notas sintéticas GET/POST, panel administrativo que refleja 403 del backend sin entregar datos, logout que intenta revocar bearer del API y luego termina sesión local. Todos los controles efectúan peticiones reales al BFF, no son elementos decorativos. No hay backend productivo ni IdP real conectados.

**Pruebas:** TypeScript sin errores, build Next.js, 3 pruebas de validaciones (origen, URL fija, identidad concreta) y HTTP smoke con servidor Next.js real: GET notas anónimo = 401, GET admin anónimo = 401, POST sin Origin = 403, POST logout sin Origin = 403. [Actions #42225751848](https://github.com/Gh0stDeveloper/smart-uni/actions/runs/42225751848).

**Pendientes:** flujos de login comprobados con IdP externo y browser, cookies tras proxy TLS/cabeceras, token refresh/rotación, CSP strict, auditoría SCA y lockfile comprometido, despliegue. No suponer que un build del portal implica cumplimiento de seguridad. Ver P09, P16, P31, P32, P35, P36 en [registro](../PENDIENTES_SMART_UNI_2_0.md).
