# 1 Análisis y línea base — auditoría de seguridad

## 1 Análisis y línea base

### 1.2 Auditoría y modelo de amenazas

**Método:** revisión estática de `core.py`, `student_data.py`, `main.py`, `ui.py`, `student_ui.py`, scripts de construcción y flujos de GitHub, contra `main` en `6da9e168787af77570a6882a009e1a82ea90c530`. Las conclusiones son propiedades observables del código, **no** un pentest ni un resultado de herramientas SAST.

#### Activos, actores y límites de confianza

**Activos:** hashes de contraseñas; identidad (nombre, correo, carrera); contactos; fechas/calendario; tareas, notas, materiales; integridad del JSON; activos visuales y builds distribuidos.

**Actores:** usuario local legítimo; otro usuario de la misma estación; proceso local con acceso al directorio de datos; archivos externos importados; contribuyente/paquete de compilación comprometido; futuro cliente o API remota (aún inexistente).

**Fronteras actuales:**
1. Formulario Tkinter → `SmartUniService.authenticate` → sesión representada por `self.user` en GUI.
2. GUI → `StudentSpaceService` con correo elegido por el llamador; los métodos verifican **existencia** del correo en JSON, no posesión de credenciales ni identidad de una sesión.
3. JSON y `materiales/` → sistema de archivos local. Un proceso con permisos de lectura del usuario no tiene una frontera criptográfica.
4. Archivos externos → copia a `materiales/` → apertura con aplicación asociada del sistema.
5. Repositorio → dependencias y workflows → EXE de distribución. La firma y los controles de actualización no existen.

#### Hallazgos priorizados (STRIDE)

| ID | Severidad | Categoría | Evidencia concreta | Riesgo y medida futura |
|---|---|---|---|---|
| R01 | Alta | Divulgación | `core.py::_write` serializa JSON sin cifrar; `student_data.py::add_material` copia archivos sin cifrar | Otros procesos con permisos de lectura pueden acceder a notas y adjuntos. Cifrar base y adjuntos en 4 y 6; permisos restrictivos ahora si se interviene el producto. |
| R02 | Alta para una futura API / Media local | Suplantación y elevación | `StudentSpaceService._read_space/_change/update_profile` reciben correo; solo comprueban que exista | Un llamador que pueda invocar esos servicios puede leer/modificar datos de otra cuenta. No reutilizar el servicio como autorización de API; exigir sesión/contexto y políticas por recurso en 2 y 5. |
| R03 | Media | Suplantación | `main.py` llama incondicionalmente `seed_demo`, `seed_student_demo`; `ui.py` muestra credenciales públicas | Credencial fija conocida para cuenta sintética; debe eliminarse antes de introducir datos reales, sin romper la demo durante la etapa 1. |
| R04 | Alta | Integridad/disponibilidad | `_write` atómico, pero sin backup/versionado; `_change` ejecuta leer-modificar-escribir sin locking | Corrupción externa y escrituras simultáneas pueden generar pérdida lógica. Añadir copias restaurables y transacciones en 4. |
| R05 | Media | Divulgación | `student_data.py` usa `mkdir` por defecto y `shutil.copy2` para documentos | En sistemas con permisos permisivos, los adjuntos pueden conservar modo del origen; comprobar permisos locales y endurecer en 4. |
| R06 | Media | Denegación de servicio | `verify_password` extrae `int(rounds)` del hash guardado y lo pasa a PBKDF2 sin tope ni validación de longitud | JSON manipulado puede disparar trabajo arbitrario o bloqueo. Definir límites y migración compatible en 3/4. |
| R07 | Media | Manipulación/disponibilidad | `_read` verifica solo tres claves, sin schema de listas/tipos y sin límite de tamaño | JSON válido pero mal formado puede producir excepciones o consumo excesivo; validar esquemas en 2/4. |
| R08 | Media | Manipulación | `add_material` valida extensión y 30 MiB, no contenido; `open_material` invoca visor del SO | Un archivo con extensión permitida puede ser peligroso en un lector externo; advertir, identificar formatos y controlar apertura, 4/9. |
| R09 | Media | Cadena de suministro | `compilar-windows.yml` instala rangos de Pillow/PyInstaller y Actions sin SHA inmutable | Builds no totalmente reproducibles, potencial cambio de dependencias; fijar versiones y añadir auditoría/SBOM en 9. |
| R10 | Media | Repudio/operación | No hay registros de auditoría, restauración comprobada ni error recovery del JSON | No es posible atribuir modificaciones ni restaurar automáticamente; diseñar historial, recuperación y pruebas en 4/9. |
| R11 | Baja | Compatibilidad | La UI usa fuentes Poppins/Roboto con sustitución automática; icono PNG empaquetado mediante `--add-data` | Diferencias visuales entre SO o builds; conservar activos y comparar capturas con revisión humana. |

**Nota sobre R02:** no se afirma un exploit remoto: todavía no existe backend; el riesgo se materializa en llamadores de confianza insuficiente y en una futura integración. **Nota sobre R01:** el hash PBKDF2 protege la contraseña de exposición literal, pero no cifra el resto de los datos.

#### Comprobaciones y límites de la auditoría

- Confirmado por lectura: PBKDF2-SHA256 con salt aleatorio de 16 bytes y 260 000 iteraciones para registros nuevos; `hmac.compare_digest` al verificar. No sustituye Argon2id planificado.
- Confirmado por lectura: `os.replace` y `fsync` evitan archivos a medio escribir en muchos fallos, pero no garantizan durabilidad de directorio, rollback ni aislamiento concurrente.
- Confirmado por lectura: el código de apertura de archivos usa `os.startfile` / `subprocess.Popen` con lista de argumentos, sin `shell=True`; no se observó inyección de shell en ese punto.
- Confirmado por lectura: no se observaron claves reales en los archivos de código examinados; **esto no equivale** a un escaneo de todo el historial ni a prueba de ausencia de secretos.
- No ejecutado durante esta auditoría: fuzzing, pentest, SAST especializado, evaluación de permisos en estaciones reales, evaluación de dependencias descargadas ni análisis dinámico de lectores externos.

#### Decisiones de contención de esta etapa

No reescribir autenticación, migrar JSON, sustituir cifrado, eliminar la cuenta demo, alterar interfaces ni integrar Rust todavía: rompería la línea base que debemos fijar. Se conservan hallazgos con trazabilidad y se exigen pruebas de regresión antes de iniciar 2.

- [x] Activos, actores y límites de confianza explícitos.
