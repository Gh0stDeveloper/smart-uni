#### Capturas y respaldo de demostración

El script `apps/desktop/tests/capture_phase1_baseline.py`, ejecutado con Pillow en sesión Tk real, genera en un directorio aislado: capturas PNG de Acceso, Panel principal, Tareas, Material y Apuntes, una copia JSON **sintética** con cuenta demo y un manifiesto `manifest.json` con SHA-256 de los archivos, SO, versión Python y commit `GITHUB_SHA`.

En GitHub Actions `desktop-tests.yml`: en Ubuntu se usa Xvfb; en Windows se captura la ventana de Tk. Cada sistema publica su propio artefacto temporal `smart-uni-phase1-<SO>`; si fallan capturas, el trabajo debe fallar y no se certifica la etapa. Los archivos JSON y capturas **no** se incorporan a Git para evitar publicar datos no sintéticos por error. El manifiesto permite verificar la integridad de respaldos descargados. Las capturas son evidencia de visualización, no una aprobación visual automática.

**Reproducción manual:**
- Windows: `python -m pip install "pillow>=10,<13"` y `python tests/capture_phase1_baseline.py --output phase1-evidence` desde `apps/desktop`.
- Linux: instalar `python3-tk xvfb` y Pillow; `xvfb-run -a -s "-screen 0 1600x1000x24" python3 tests/capture_phase1_baseline.py --output phase1-evidence`.
- Restauración de prueba: la suite copia el JSON generado, comprueba SHA-256, lo repone en el directorio aislado y vuelve a autenticar a la cuenta ficticia. **No existe restauración para datos reales en la app.**
