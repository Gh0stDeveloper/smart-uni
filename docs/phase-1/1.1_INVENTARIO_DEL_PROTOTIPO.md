#### Pantallas y comportamiento que debe preservarse

Acceso, registro, panel principal, cursos, horario, anuncios, Inicio académico, Perfil, Amigos, Calendario, Material, Tareas y Apuntes. El menú hamburguesa es único y aparece a la izquierda; no introducir panel derecho suplementario. La visualización se configura a 1260×840, con mínimo 1000×680. Las funciones del espacio estudiantil se organizan en ocho materias predefinidas, independientes del catálogo de cuatro cursos de demostración.

#### Persistencia y tipos de datos

- `~/.smart_uni/data.json` por defecto; sobreescribible con `SMART_UNI_DATA`. El JSON contiene `version: 1`, `students`, `courses`, `announcements` y, al usar el espacio académico, `student_spaces` por email.
- Cada estudiante guarda nombre, correo, carrera y `password_hash` en formato `pbkdf2_sha256$260000$salt$digest`. No existe servidor ni autenticación federada.
- En `student_spaces` se almacenan amigos, eventos, tareas, apuntes, materiales y bandera de demo. Contiene información potencialmente privada en texto claro; **no** es una base cifrada.
- Los archivos adjuntos se copian a `materiales/<uuid32>.<ext>`, junto al JSON, con límite nominal de 30 MiB y lista de extensiones `.pdf .txt .md .docx .xlsx .pptx .csv .png .jpg .jpeg`. La extensión no prueba que el contenido sea seguro.
- `_write` crea un temporal, ejecuta `fsync` y `os.replace`. Esta atomicidad de sustitución **no** ofrece bloqueo entre procesos, historial ni recuperación automática.
- No hay datos reales versionados en el repositorio. Los JSON generados por pruebas deben ser sintéticos y permanecer únicamente en artefactos de CI.

#### Identidad visual y recursos

- Icono original: `apps/desktop/design/previews/00_isotipo_smart_uni.png` (Git blob `e59066d4c32c8e65ad763335f87b4f477f3c92b4`), SVG fuente `apps/desktop/design/figma_svg/00_isotipo_smart_uni.svg` (Git blob `429106ade23f1f469f5784327d6bb6e994e3e43d`).
- Tokens duplicados idénticos: `apps/desktop/design/tokens.json` y `packages/design-system/tokens.json` (Git blob `45595110d1d7897f2b628a4ae7ae35465f7a5305`). Azul `#2B80EC`, turquesa `#2BB2C4`, Poppins y Roboto.
- `design/build_icon.py` genera ICO con Pillow; `design/make_figma_assets.py` utiliza CairoSVG opcional; `design/record_demo.py` usa Pillow y herramientas de video para exhibiciones. Estas utilidades no equivalen a dependencias de ejecución del prototipo.
- Se preservan los activos, las fuentes previstas, la distribución y la navegación. Capturas generadas en CI sirven de referencia visual, no sustituyen revisión humana pixel a pixel.

#### Componentes planificados, no existentes

`apps/android`, `apps/web`, `core/rust` y `services/api` solo contienen README y documentación. No hay APK, cliente Android, FFI Rust, API, PostgreSQL, SQLite cifrado, E2EE ni sincronización ejecutables.

#### Dependencias y cadena de suministro

Ejecución: Python 3.10+, stdlib, Tkinter/Tcl del SO. Pruebas de referencia en CI: Python 3.12, Linux/Xvfb y Windows. Compilación: PyInstaller `>=6,<7` y Pillow `>=10,<13` en Windows; script Linux instala PyInstaller. Diseño opcional: Pillow, CairoSVG, ffmpeg. No hay lockfile o hash de paquetes; GitHub Actions utiliza etiquetas de versión (`checkout@v4`, `setup-python@v5`). Fijación y SBOM quedan como mejoras pendientes.
