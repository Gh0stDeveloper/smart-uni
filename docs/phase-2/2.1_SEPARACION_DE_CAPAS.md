# 2 Contratos y sistema de diseño — separación de capas

## 2 Contratos y sistema de diseño

### 2.1 Separación de capas de escritorio

**Objetivo:** conservar exactamente el diseño y los casos de uso mientras desacoplamos componentes del prototipo, sin migrar todavía a Rust, SQL o cuentas remotas.

| Capa | Archivo | Contrato y compatibilidad |
|---|---|---|
| UI Tkinter | `smart_uni/ui.py`, `student_ui.py` | Pantallas originales, `app.user` conservado mediante propiedad |
| Sesión local | `smart_uni/session.py` | `SessionState`, estado efímero sin contraseña ni tokens, vaciado al cerrar sesión |
| Servicios/casos de uso | `smart_uni/core.py`, `student_data.py` | `SmartUniService`, `StudentSpaceService` y sus métodos originales |
| Dominio | `smart_uni/domain.py` | Validación de correos/registro y verificación PBKDF2 heredada, ejemplos académicos |
| Persistencia | `smart_uni/repository.py` | `RecordRepository` como puerto, `JsonRepository` como adaptador JSON v1 |

Se mantienen `SmartUniService._read/_write` como fachadas de compatibilidad y `smart_uni.core.ValidationError`, `verify_password` y `validate_email` como importaciones disponibles. `JsonRepository` conserva la escritura temporal + fsync + reemplazo del formato existente.

**Riesgos no mitigados:** el `StudentSpaceService` antiguo continúa aceptando correo del llamador y no constituye una autorización confiable (R02); JSON y materiales siguen sin cifrar (R01). La sesión no es un sustituto del control de acceso por recurso. La migración transaccional a SQLite corresponde a 4, autenticación remota a 5 y criptografía a 6.

**Regresión:** `tests/test_phase2_layers.py` verifica inyección de repositorio alternativo, JSON preexistente sin reescritura, importaciones heredadas, funciones académicas y ciclo de vida de sesión. La suite completa Windows/Linux y capturas de pantalla de [1.3](../phase-1/1.3_PRUEBAS_Y_REGRESION.md) son obligatorias antes de cerrar esta subfase.

**Criterios de aceptación:**
- [x] Separación ejecutable entre dominio, aplicación, persistencia, UI y estado de sesión.
- [x] Compatibilidad explícita para rutas públicas usadas en prototipo y pruebas.
- [ ] Ejecución de CI Windows/Linux, captura y compilación en verde para commit de 2.1.
