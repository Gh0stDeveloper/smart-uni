# 4 Persistencia local y funcionamiento offline

## 4.2 Migración JSON y respaldos

**Estado técnico:** migración transaccional y restauración cifrada probadas en Windows/Linux con interrupciones simuladas. La fuente de datos se preserva intencionadamente; no está implantada todavía limpieza de plaintext o recuperación de claves multi-equipo.

**Código:** apps/desktop/smart_uni/migration.py.

### Migración

- Solo JSON v1 de máximo 20 MiB, sin enlaces simbólicos; valida listas y estructura superior.
- Calcula SHA-256 del JSON origen antes de crear staging SQLCipher. Se guarda el digest en tabla metadata cifrada.
- SQLCipher temporal se valida con integrity_check y control de contenido. Se vuelve a calcular hash del JSON antes de publicar; si ha cambiado, se rechaza.
- Publicación mediante os.replace en el mismo sistema de archivos y fsync de directorio POSIX. No se sobrescribe destino ya existente y no se borra el JSON. Un corte antes de promoción elimina staging y deja origen intacto, permitiendo reintento.
- **Advertencia:** si ya existían materiales externos, éstos NO están incluidos en el snapshot ni el cifrado. El JSON sin cifrar queda como copia de recuperación hasta disponer de procedimiento seguro de depuración.

### Backups cifrados y restauración

- create_backup bloquea escrituras, copia bytes SQLCipher a temporal privado, hace fsync, verifica llave/cifrado/integridad y promueve backup sin sobrescritura. No hay exportación JSON legible.
- restore_backup valida copia completa ANTES de modificar destino; copia a staging, crea archivo pre-restore cifrado con estado anterior y lo sustituye atómicamente. Es responsabilidad del llamador cerrar el resto de conexiones. La clave de SO original sigue siendo necesaria; copiar DB a otro dispositivo sin llave NO permite restaurarla.
- Probar restauración no equivale a un plan de recuperación tras fallo de disco o energía, a retención de backups ni a recuperación remota.

### Evidencias y criterios

test_phase4_migration.py verifica preservación de bytes JSON, migración y reintento tras fallo simulado, backup con hash, recuperación de contenido anterior, rechazo de backup corrupto y fallo antes de promoción. Esos tests se ejecutan con SQLCipher auténtico en Windows y Ubuntu.
