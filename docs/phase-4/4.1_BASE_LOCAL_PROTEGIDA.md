# 4 Persistencia local y funcionamiento offline

## 4.1 Base local protegida

**Estado técnico:** implementada de forma opt-in en Windows/Linux, con pruebas CI. **No** sustituye todavía el almacenamiento por defecto ni es adecuada para producción con datos personales reales.

**Código:** apps/desktop/smart_uni/secure_storage.py, storage_mode.py y requirements-secure.txt.

### Modelo y límites

- sqlcipher3==0.6.5 sobre CPython 3.12, sin degradación a sqlite3 estándar; se comprueba PRAGMA cipher_version e integrity_check.
- Base cifrada en disco que contiene snapshot JSON v1, metadatos y cola outbox. SQLCipher usa journal_mode DELETE, synchronous FULL, secure_delete, transacciones BEGIN IMMEDIATE; POSIX 0600 para el archivo. Snapshot con máximo 20 MiB.
- OSKeyStore consulta Windows Credential Locker, Secret Service o KWallet según plataforma; clave aleatoria de 32 bytes, almacenada en keyring del SO con identificador estable derivado de ruta. Si falta clave de base existente, backend seguro, o SQLCipher, aborta sin abrir una base en claro ni crear clave nueva.
- Tests inyectan MemoryKeys (no equivalen a probar WinVault/SecretService en una cuenta real). El cifrado de base no protege frente a malware dentro de la misma sesión autorizada ni cifra automáticamente archivos/materiales sueltos.
- Selección explícita SMARTUNI_STORAGE=secure; por defecto SMARTUNI_STORAGE=legacy conserva todas las pantallas, icono, ejemplos y formato JSON histórico. El modo seguro no siembra automáticamente cuenta demo con contraseña pública.
- Si el JSON legacy existe y no hay base cifrada, el modo seguro usa la migración 4.2. Los materiales aún se bloquean en el modo seguro para no copiarlos sin cifrar.

### Reproducción sin modificar el JSON original

1. Preparar Python 3.12, Tkinter y un backend keyring real y desbloqueado.
2. Instalar dependencias: pip install -r apps/desktop/requirements-secure.txt.
3. Definir SMARTUNI_STORAGE=secure y arrancar python apps/desktop/main.py.
4. Confirmar que se crea data.sqlcipher, verificar permisos y ausencia de cabecera SQLite sin cifrar. Si falla la clave, no borrar la base ni generar un reemplazo.
5. El EXE heredado distribuido en CI NO incorpora SQLCipher: no usarlo para validar esta función. Instalarlo y probarlo en un equipo real es parte de P22/P25.
